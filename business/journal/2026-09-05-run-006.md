## Two bugs this surfaced

**1. A header row shipped as publishable content.**

The new skill titled its table column `| Excuse | Reality |` instead of
`| Rationalization | Reality |`. My parser stripped headers by matching the literal
word "rationalization", so the header row sailed through and became an atom:
`hook="Excuse", payoff="Reality"`.

That was sitting in the pool that feeds Instagram slides. A slide reading **"Excuse"**
in 86px type would have gone out under the brand.

Fixed structurally rather than by adding "excuse" to a keyword list: a markdown table's
header is always the row above the `|---|` separator, so the parser now cuts there. It
no longer cares what the column is called, which matters because upstream will keep
adding skills and I won't get to review their table headers first.

My first attempt at the fix left a `return` above the new logic — dead code, and the
bug would have persisted. Caught it by reading the patched function back instead of
trusting the edit applied cleanly.

**2. The classifier had real false negatives.**

All 11 new rationalizations landed in "unmatched," and cluster counts didn't move at
all. That's a suspicious result, not a clean one — it means the rules were matching
phrasing, not shape. Four were genuine misses:

- "We'll add constraints once the code settles" → deferral (regex wanted "once *we*")
- "This will slow the agent down" → ceremony (regex wanted "slow *me/us* down")
- "The tests are the constraints" → false-proxy (textbook: one real signal standing in
  for another it doesn't cover)
- "I'll remember what our standards are" → confidence (memory offered as verification)

Broadened those four rules. Left "We can't hit 80% coverage" unmatched — it doesn't fit
a cluster, and forcing it would be tuning until everything fits, which is the failure
the script's own comment warns about. Unmatched is still 76 of 163; that pile is
genuinely half the corpus and probably holds a seventh cluster. Not inventing one today.

## The stale-number problem, which is the real lesson

Issues 001 and 002 were drafted against a 24-skill library and sat awaiting approval.
The moment upstream made it 25, **every count and percentage in both drafts became
wrong** — headline stat, discipline counts, the "other N rationalizations" teaser, the
cluster sizes in issue 002's opener.

Nothing about the drafts changed. The ground under them did.

Corrected both against freshly derived figures:
- deferral: 16 of 24 (67%) → **17 of 25 (68%)**, n=19 → 20
- total rationalizations: 153 → **163**; remainder teaser 134 → **143**
- technically-true cluster: 14 across 12 → **15 across 13**
- ceremony (issue 002's teaser): 15 disciplines → **16**, still rank 2

Re-verified all six quoted rationalizations in issue 002 are still verbatim in source.
Swept both drafts for residual stale figures — clean.

This is a new *class* of the standing failure mode. The old one was inventing a number.
This one is a number that was correct when written and rotted underneath me. Written
into STATE.md as a live dependency risk: any upstream sync requires re-deriving every
published figure before anything ships.
