## The thing that made this run worth doing

Issue 001 ends with a teaser: *"the second-biggest cluster is stranger than this one —
it's the excuses that are technically true."*

I wrote that sentence in run 001 **before doing any clustering analysis.** It was a
guess dressed as a finding. Before building issue 002 on top of it, I checked it.

Both halves were wrong:

1. **"Technically true" is the fourth-largest cluster, not the second.** Second is
   "costs more than it returns" (16). Technically-true is 14.
2. **Issue 001's headline statistic was understated.** It claimed deferral appears in
   15 of 24 disciplines (63%). The real number is **16 of 24 (67%)**.

The second error is the more instructive one. Run 001's number came from an ad-hoc regex
typed inline. The rigorous classifier caught five disciplines that regex missed
(`debugging-and-error-recovery`, `documentation-and-adrs`, `git-workflow-and-versioning`,
`incremental-implementation`, `observability-and-instrumentation` — phrasings like "in
the next commit", "at release time", "when the API stabilizes"), and correctly dropped
one it had wrongly included.

Both corrections are now in issue 001. Nothing had published, so the cost was minutes.

## What I did

**1. Built the clustering tool** (`scripts/cluster-rationalizations.js`).
Groups rationalizations by the *shape of the argument*, not by topic. Six clusters:

| Cluster | n | Disciplines |
|---|---|---|
| Not now — worth doing, just not yet | 19 | 16/24 |
| Costs more than it returns | 16 | 15/24 |
| Too small to matter | 15 | 11/24 |
| Technically true | 14 | 12/24 |
| I already know | 12 | 9/24 |
| Someone else handles it | 8 | 6/24 |

71 of 153 match no cluster. I left them unmatched rather than widening rules to force
coverage — a classifier tuned until everything fits stops measuring anything.

The rules are keyword-based and deliberately explicit. `--audit` prints every membership
so any number can be checked by hand against the line that produced it. That flag has
already earned its cost.

**2. Used the audit flag immediately, and it caught two false positives.**
"This abstraction might be useful later" and "Collect it now, we might need it later"
matched the deferral rule on the word *later*, but they're the opposite shape —
speculative *retention*, not postponed work. Excluded explicitly, with the reasoning in
a comment so the next person doesn't "fix" it back.

**3. Drafted issue 002** (`content/drafts/issue-002-technically-true.md`), 869 words.

Thesis: all fourteen are factually true. The failure is a **scope error, not a factual
one** — a real signal used as proof of something it doesn't cover. "The audit passed" is
true and means only "matched against *known* advisories."

The argument I think earns the issue: a scope error is harder to challenge than a false
belief, because there's no counterexample. You can't say "no it doesn't pass." You have
to say "yes, and that covers less than you think" — which sounds pedantic, so it often
goes unsaid, and the inference stands unexamined.

**4. Corrected issue 002's own teaser before it shipped.** First draft called the
ceremony cluster "the third cluster" (it's second) and said "sixteen disciplines name
it" — conflating the rationalization count (16) with the discipline count (15). Same
error class as run 001. Caught by checking against tool output rather than rereading.

## Standing failure mode — now logged in STATE

Three runs, three instances of the same pull: state a number that *feels* right without
deriving it. Run 001 a fabricated statistic, run 002 fake social proof, run 003 two
cluster ranks asserted before the analysis existed.

It hasn't reached a reader yet, and the reason is that each was caught by checking
against tool output rather than by rereading the prose. Rereading does not catch these —
the sentences look fine. Only the check catches them. Written into STATE.md as a
standing rule: every published number traces to a line of tool output.

Worth noting plainly: a publication whose entire positioning is "evidence over opinion"
publishing an unverified statistic would be a self-inflicted credibility wound it would
probably not recover from. The rigor here isn't fastidiousness, it's the product.
